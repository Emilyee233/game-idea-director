# Contributing

Contributions should improve a clearly identified design or production problem.

## Reference contributions
A new reference should:
- State when it should be loaded.
- Define its scope and non-goals.
- Provide actionable reasoning, not generic advice.
- Identify common failure modes.
- Distinguish theory from validation.
- Avoid private or copyrighted project material.
- Be added to `references/reference-index.md`.

## Changes to shared rules
Avoid duplicating shared behavior in multiple files. If a rule affects authority, privacy, permissions, or global status definitions, update `SKILL.md` and keep specialist references subordinate.

## Tests
Add or update evaluation cases for behavior changes.

## Examples
Use independently fictional examples. Do not submit private client/user projects as examples without explicit rights and review.
