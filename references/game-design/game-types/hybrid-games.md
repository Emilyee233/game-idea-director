# Hybrid Game Design

A hybrid is not automatically stronger because it contains more systems. Identify why the activities belong together.

## Integration analysis
For each major activity identify intended experience, verbs/decisions, controls, time scale, resources/state, progression, failure/recovery, and content burden. Then examine what each contributes to the other, shared state, conflicting incentives, pacing transitions, primary/supporting roles, and audience mismatch.

## Useful integration patterns
One activity creates resources/options for another; provides pacing contrast; changes conditions of another; shares strategic state; or is emphasized by player choice. These are patterns, not recipes.

## Common failures
Two good games stitched together; one mode is mandatory busywork; progression in one trivializes another; controls/pacing demand incompatible skills; production scope multiplies.

## Prototype
Test the connection between activities, not merely each activity in isolation.
