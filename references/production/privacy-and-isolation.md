# Privacy and Project Isolation

## Purpose
Prevent private project material from leaking into public Skill content, examples, or unrelated work.

## Separate
- Public Skill source.
- User project files.
- Temporary working files.
- Generated artifacts.
- External services/connectors.
- Logs/history controlled by the host platform.

## Rules
- Access only authorized project material.
- Do not copy private project-specific content into public examples or references.
- Use independently invented examples for public documentation and tests.
- Do not publish/upload project material without explicit authorization.
- Before public release, inspect repository contents and history when tools permit.
- Redact identifying paths, names, secrets, private URLs, and project-specific content when creating public examples.

These rules guide behavior; they are not a technical sandbox or confidentiality guarantee.
