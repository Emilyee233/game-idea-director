# Project Management

## Purpose
Convert design into a manageable sequence of work while protecting scope and dependencies.

## Plan around deliverables
Prefer milestones that produce observable results:
- A mechanic can be played.
- A system can be tested.
- A representative asset is integrated.
- A data flow is proven.
- A vertical slice section is reviewable.

Avoid milestones defined only as "work on X".

## Task design
A task should have:
- Outcome.
- Owner.
- Dependencies.
- Scope.
- Acceptance criteria.
- Status.
- Risks/blockers.

## Dependencies
Distinguish:
- Hard dependency: cannot proceed.
- Soft dependency: can proceed with assumptions/placeholders.
- Shared-resource conflict: can proceed only with coordination.

## Scope change
When new work is proposed, identify what it displaces in time, budget, or attention. Do not let backlog growth masquerade as progress.
