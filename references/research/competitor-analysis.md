# Competitor and Reference Game Analysis

## Purpose
Learn design logic from existing games without reducing analysis to feature copying.

## Analyze
- Target experience.
- Player actions.
- Meaningful decisions.
- Core structure/loops.
- Mechanics and systems.
- Information and feedback.
- Progression/content.
- Friction and common complaints.
- Production implications.

## Causality caution
A successful game containing a feature does not prove that feature caused its success.

## Transfer
For each lesson ask:
- What problem does this design solve?
- Under what conditions does it work?
- Does the current project share those conditions?
- What independent implementation would serve the same principle?

Do not copy protected art, writing, characters, maps, code, or other expressive content.
